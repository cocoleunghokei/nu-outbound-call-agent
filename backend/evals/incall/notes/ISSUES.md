## Biggest issues and fixes

Hard pass went from 70.4% (eval 2026-11-18T0303Z) to 96.6% (eval 2026-11-18T1711Z). Each row is one kind of problem, with a case as an example. Update this table when an issue is fixed or a new one shows up.

| Issue | Example | Fix | Result |
| --- | --- | --- | --- |
| **No tool call:** the agent says its decision out loud ("yes, that works") without first recording it through a tool. Our safety checks only see tool calls, so a spoken yes goes straight to the business unchecked | C4-04: said "Friday at 2pm works" to an offer that broke the user's rule | Tool-first rule at the top of the prompt, with a worked example; field keys listed in `<share_freely>` | 12 checks (03:30) → 0 since 04:01 |
| **Offer misjudged against the rules:** the model compared the business's offer with the user's rules itself and got it wrong, for example deciding a time fits when it doesn't | C4-05: treated 3pm as "before 3pm"; noon as "morning" | The agent writes the offer down as data; Python compares it with the brief's rules (Q13) | Comparison slips gone |
| **Wrong year on dates:** the agent wrote offers with last year's date, so our checks compared them with the wrong day and refused correct answers | Wrote 2025-11-19, so the gates refused correct answers | Python moves the date to the brief's year; prompt lists dates with weekday and year | 83 → 0 offers dated 2025 |
| **Accepting on a missing detail:** the agent accepted an offer without writing down a detail the user's rules depend on (such as the time), so nothing could check it | C4-05: "took the Friday morning fallback" with no time; the business never offered Friday | Missing-detail gate: no accept on an offer that leaves out what the rules need | Fixed (04:01 on) |
| **Too many or needless counters:** a counter is the agent turning an offer down and asking the business for something else. | **Booked, but no outcome reported:** the business confirmed the booking, but the agent never recorded the result, so the user would see "needs follow-up" for a call that worked | G-11: "You're all set for Thursday at 2" → accepted, never called `report_outcome` | Tool result says "They already said it is booked: call report_outcome now" | Fixed |

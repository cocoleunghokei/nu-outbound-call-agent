## What we found
- **Worse: Hard failures 3 → 7; failed checks 13 → 20.** Nearly every failure is "no tool call".
- **The transcripts show no tool calls at all** in C4-01, C4-05, C4-06 and C4-12: the agent spoke sensible words and never called `report_decision` or `ask_user`. C4-01 said "That works well" to a perfect offer and logged nothing; C4-05 countered twice in words; C4-12 said "There's no referral involved", the invented "no detail" again.
- **The gates were not the cause:** `gates-quiet` passed everywhere, so no action was refused. The model simply didn't act.
- **The prompt change was small** (one sentence about logging the counter in the same reply), and the run reverted rules that worked in the third run (C4-01, no inventing), so the change of behaviour is unlikely to come from that sentence alone.

## Likely causes (not settled)
- **Variance:** one run per case, provider default temperature (the live assistant uses the default too, `app/calls/assistant.py`).
- **A new model behind the `deepseek-chat` alias:** DeepSeek can move the alias between runs. Not recorded until now.
